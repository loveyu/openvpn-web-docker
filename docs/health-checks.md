# 健康检查

[返回项目首页](../README.md)

容器与 OpenVPN 的健康状态分别报告，概览和健康检查页同时展示，OpenVPN 页展示隧道健康状态：

- **容器健康**：`/healthz`
  供 Docker 使用，仅检查管理进程、VPN 健康检查任务及出口防火墙的默认拒绝策略；正常返回
  `200`，内部故障返回
  `503`。VPN 未配置、连接中、断线或手动停止均不直接影响容器健康。HTTP/SOCKS5/SSH 的进程与监听状态另行展示。
- **OpenVPN 健康**：`/api/status` 的 `health.vpn`
  区分未配置、已停止、连接中、检测中、正常、异常；检查实际连接状态与 `tun0` IPv4 地址，不受“启动时自动连接”开关影响。可选追加 Ping、TCP 或 HTTP 探测，固定通过
  `tun0`，不会使用允许直连的 HTTPDNS 路径来证明隧道可用。

网络探测默认关闭。启用后，默认目标 `1.1.1.1`、TCP 端口 `443`、HTTP URL `https://www.qq.com`、GET、预期状态 `200`、间隔 `30` 秒、超时 `5` 秒、Ping 次数
`1`。超时限制整次探测，多个 Ping 共享该时间上限。结果随配置、连接变化失效，过期结果显示为等待检查；手动测试单独返回结果，不修改定时失败计数、不执行恢复动作。

**默认连续失败 `3`
次后重启内部 OpenVPN 服务**。连接故障和已启用的网络探测失败都会累计；成功后清零。界面可调整检查间隔、失败阈值、恢复动作和动作冷却时间（默认
`120` 秒）。动作可选：

| 动作 | 行为 |
| --- | --- |
| 仅记录 | 报告异常，不执行恢复 |
| 软重连 | 向 OpenVPN 发送 `SIGUSR1`，使用当前配置重新连接 |
| 重启 OpenVPN 服务（默认） | 通过 Supervisor 重启内部 OpenVPN 进程 |
| 重新应用 VPN 配置并重连 | 加载已保存的 VPN 配置并重连；Auto 模式重新探测选点，手动模式保留指定 endpoint |

每次动作后重新累计失败次数，并遵守冷却时间；最近动作、时间和结果显示在健康检查页。未配置 VPN、手动停止及配置切换期间不执行恢复。恢复动作只操作 OpenVPN，不重启容器或其他服务。Docker 的
`unhealthy` 标记本身不会触发 `restart: unless-stopped`。

网络探测遵循[出口保护规则](networking.md#出口保护与参数边界)；服务日志位置与查看命令见[存储与权限](storage.md)。
